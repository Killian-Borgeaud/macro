# Cognitive Preferences

How the user learns best. Read by any skill that generates explanation, lecture, quiz, exercise, exam, or essay content. Subject-agnostic — applies across Macro, Micro, and any future subject in this workspace.

## Explanation structure

Follow this sequence for every explanation:

1. **Intuition first**: What is this thing, concretely? What object is it? What does it represent geometrically, physically, or logically? Never start with a formula or abstract definition.
2. **Invite validation**: After the core intuition, pause for the user to rephrase ("so basically X means Y?"). Structure explanations so this checkpoint feels natural.
3. **Comparison table** if contrasting concepts — the user grasps contrasts very quickly. Use a table, never inline prose like "X is like A but Y is like B."
4. **Formula with symbol-by-symbol explanation**: Only after intuition is established. Every symbol in a formula must be explained in words. The user struggles when notation doesn't map clearly to a concept they can visualize.
5. **Worked example**: At least one concrete, non-trivial example with realistic numbers. The user learns by doing and will immediately ask for practice if none is provided.

## What the user grasps quickly

- Conceptual contrasts (X vs Y framings)
- Procedural algorithms once given as clear step-by-step checklists
- Definitions, once grounded in what the object actually is
- Cross-domain analogies between subjects they already know

## What the user struggles with

- **Symbolic representation**: When mathematical notation doesn't connect to a concrete meaning. Matrix expressions, variance notation, integral transforms — the symbol-to-meaning bridge is the hard part. Always explain what the mathematical object IS before manipulating it.
- **Multi-method ambiguity**: When multiple approaches exist and it's unclear which to use or why they give different-seeming results. Always state which method to use when, and why.
- **Dynamic/path reasoning**: Why a trajectory must behave a certain way, stability arguments. Ground these in concrete "what would happen if" scenarios.
- **Vocabulary retention**: The user retains mechanics well but forgets names. Introduce the concept first, then the name. In quizzes, specifically test naming.

## Formatting

- Short paragraphs (3-4 sentences max)
- Tables for any comparison
- "One Sentence Version" or "Memory Trick" callouts for key takeaways
- No dense bullet walls — prefer short paragraphs with clear breaks

## Depth

- Default: stay within exam scope
- Go deeper when the user asks "why" or "how does it actually work"
- Flag out-of-scope content: "Beyond exam scope, but useful to understand:"

## Tone

- Casual but precise — never dumbed down, never unnecessarily formal
- The user is intelligent and cross-disciplinary but new to the specific material
- When the user challenges an explanation ("do you actually understand this or are you just spitting theorems?"), respond with genuine geometric/concrete intuition, not restated formalism
